# Learning Path

## Teaching model

Each lab follows the same learning loop:

1. **Observe** a repository or GitHub state.
2. **Predict** what evidence should change.
3. **Act** through GitHub Copilot CLI.
4. **Verify** with a deterministic checkpoint.
5. **Reflect** on control, safety, and human responsibility.
6. **Persist** the result in Git, GitHub, or an evidence file.

The learner cannot complete the course by reading. Labs require repository files, Git worktrees, GitHub issues, comments, test results, and a pull request.

## Competency levels

| Level | Labs | Demonstrated capability |
|---|---|---|
| Observer | 00-01 | Can distinguish a prompt from a measurable closed loop |
| Designer | 02-03 | Can encode knowledge and use durable work discovery |
| Operator | 04-06 | Can isolate execution and enforce independent verification |
| Governor | 07-08 | Can automate safely and retain human control |

## Assessment

Every lab is worth 10 points. Automated checks confirm objective evidence; reflection prompts are intended for instructor or peer review. A complete capstone requires all local checkpoints plus a qualifying GitHub pull request.

Automated success is necessary but not sufficient for production deployment. The learner remains responsible for understanding and approving the final change.
